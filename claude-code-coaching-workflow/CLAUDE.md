# 月度教練分析專案規則

本專案把「當月改變表格」與「教練逐字稿」轉成可追蹤、可回饋、可行動的月度教練分析。

## 預設工作流

- 使用者要求分析表格、逐字稿、教練紀錄或 1-on-1 紀錄時，使用 `monthly-coaching-analysis` skill。
- 固定分析順序：當月改變表格 → 逐字稿證據 → 事件具體化 → 成功因素 → 慣性模式 → 下一步行動 → 驗證方式。
- 正式輸出放在 `outputs/monthly-analysis/`。
- 不覆寫輸入檔；若同名輸出已存在，先比較內容並詢問或建立帶版本標記的新檔。

## 證據與判斷

- 優先使用同仁自己的原話與表格欄位作為證據。
- 區分本人貢獻、團隊貢獻、主管要求與環境因素。
- 每個重要判斷都要能回到輸入證據；證據不足時明確標示「低信心觀察」。
- 慣性模式只能寫成可被後續驗證的教練假設，不得貼人格或病理標籤。
- 優勢必須轉成可複製行為；問題分析必須落到下一步與驗證方式。
- 不捏造缺失的姓名、日期、角色、事件、動機、主管或結果。

## 多人分析防錯

- 批次開始前建立姓名、月份、表格、逐字稿、輸出檔的來源對照表。
- 一次只分析一人；個人報告只能使用該人的來源。
- 每人先列出至少三個專屬線索，輸出後檢查是否混入他人的姓名、專案、工具、同事互動或下一步。
- 姓名、月份、檔名或內容稱呼衝突時，停止該份正式輸出並標示「來源需確認」。

## 寫作與隱私

- 使用繁體中文，口吻溫暖、具體、尊重且可行動。
- 不用「持續加強」等空泛語句；寫清楚何時做、做什麼、如何知道有效。
- 不在輸出或 log 放入完整逐字稿、不必要的個資、客戶機密或私人聯絡資訊。
- 正式輸出必須同時產生 validation report；未通過時不得宣稱完成。

## 專案範圍

- 預設只建立本機 Markdown 分析與檢核報告。
- 未經使用者明確要求與權限確認，不寄信、不上傳、不回填外部系統。
